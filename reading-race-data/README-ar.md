# بنوك سباق القراءة المرتبطة بقائمة السماح

هذه وحدة بيانات مستقلة، غير موصولة بواجهة التطبيق أو أي سباق قائم. أُنشئت بإذن Telegram 363468 بتاريخ ٢١ نوفمبر ٢٠٢٦، ٢٢:٣٦:٠١ +٠٣. اعتماد التسجيلات مصدره المراجعة البشرية Telegram 357647. لا يجيز ذلك بناء الألعاب أو الدمج أو النشر.

## المحتوى

- `letters.json`: بنك مستقل من ٢٧ حرفًا بالفتحة.
- `syllables.json`: بنك مستقل من ٢٠ مقطعًا بالفتحة.
- `words.json`: بنك مستقل من ٢٥ كلمة ثلاثية بالفتحة، تسجيل الكلمة الكاملة فقط.
- `allowlist.json`: قائمة السماح الأصلية والبصمات وحالات الحظر الخمس.
- `human-review-results.json`: سجل المراجعة البشرية الكامل، ٧٧ عنصرًا.
- `approved-data.mjs`: سجل ثابت مجمد مشتق من الـ٧٢ عنصرًا المعتمدة، يستخدمه الفاحص وقت التشغيل. لا يقرأ قائمة بديلة من الشبكة أو التخزين.
- `reading-banks.mjs`: رابط البنوك والتحقق من كل خانة صوتية.
- `tests/banks.test.mjs`: اختبار مستقل قابل لإعادة التشغيل باستخدام Node 22: `node reading-race-data/tests/banks.test.mjs` من جذر المستودع.
- `tests/node-results.json` و`tests/browser-results.json`: نتائج الاختبارات المنفذة.

## واجهة الوحدة للاستخدام اللاحق

`createReadingBank(section, {loadBytes})` يقبل أحد الأقسام `letters` أو `syllables` أو `words`، ودالة تقرأ بايتات المسار المحدد أو تفشل. لا تُعطى الدالة مسارًا من المستخدم، بل المسار الأصلي الموجود في قائمة السماح.

`inventory` يصف العناصر المعتمدة فقط، ولا يحتوي صوتًا جاهزًا للتشغيل. لا تعتبر أي خانة مقبولة إلا بعد نجاح `acceptSlot` أو `createQuestion`.

`acceptSlot({id, path, sha256, role})` يفحص المعرف والقسم والمسار والبصمة المعلنة، ثم يحسب SHA-256 للبايتات المحملة ويقارنه بالبصمة البشرية المعتمدة. الأدوار المسموحة: `question` و`answer` و`distractor` فقط. كل الأدوار تمر بالتحقق نفسه. الناتج يتضمن Blob مستقلًا من نسخة البايتات المتحقق منها، وليس رابط الملف الأصلي الذي يمكن تغييره بعد الفحص. يجب أن يستخدم المشغل المستقبلي هذا الـBlob لا أن يعيد جلب المسار بنفسه.

`createQuestion({question, answer, distractors})` يفرض أن السؤال والإجابة الصحيحة للمعرف نفسه، وأن المشتتات مستقلة ومختلفة ومن القسم نفسه، ويتحقق من جميع التسجيلات قبل إرجاع السؤال. يحتاج مشتتًا واحدًا على الأقل. يفشل الطلب كله إن فشلت خانة واحدة. يعيد كائنًا مجمدًا، ولا يعيد نتيجة جزئية صالحة.

لا بدائل، لا تخمين أسماء ملفات، لا رجوع إلى المستويات القديمة، لا مسح مجلدات، ولا تركيب تسجيلات. إذا لم تتوفر Web Crypto أو فشل جلب الملف أو تغيّرت بايتاته، يُرفض الصوت ولا يستبدل. يعمل الفحص في بيئة متصفح آمنة تدعم Web Crypto وBlob، أو Node 22 للاختبارات. لم تُضف أي تبعيات للتطبيق.

نمط الكلمات `whole-word` فقط، ولا يوجد دور لمكونات الدمج أو API لتشغيلها. تمرير بيانات دمج إضافية إلى إنشاء السؤال مرفوض. لا يوجد تشغيل صوتي داخل هذه الوحدة.

## التحقق المنفذ

اختبار Node: ٧٦٣ تحققًا ناجحًا، منها ٢١٦ قبولًا عبر الأدوار الصوتية، و٤٥ رفضًا للعناصر الخمسة عبر الأقسام الثلاثة والأدوار الثلاثة، وإنشاء ٧٢ سؤالًا مع إجابة ومشتت معتمد. شمل تغير البصمة والمسار والمعرف والقسم، البايتات التالفة، انتحال صوت محظور تحت معرف معتمد، الملف المفقود، إجابة غير مطابقة، خيارات مكررة، ومكونات دمج ممنوعة. كل تحميل يعاد فحصه؛ تغيير محتوى مخزن مؤقتًا لا يتجاوز الفحص، وتغيير بايتات المصدر بعد التحقق لا يغير الـBlob المعاد.

اختبار متصفح Chromium فعلي: ٧٢ سؤالًا متحققًا منها و٤٥ رفضًا، باستخدام fetch وWeb Crypto وBlob الأصليين. هذا اختبار وحدة بيانات، وليس اختبار iPhone أو لعبة أو واجهة مستخدم.

مطابقة الـ٧٤ تسجيلًا المتاح مع بصمات المراجعة نجحت، وتشمل الصوتين المحظورين للتأكد من أنهما لم يُعدلا. ملفات التطبيق القائمة والصوت والتقدم والمحرك لم تتغير. الوحدة لا تقرأ أو تكتب بيانات الطلاب أو التخزين.

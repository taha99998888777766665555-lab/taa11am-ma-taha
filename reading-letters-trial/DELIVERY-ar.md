## التعديل الأخير والاختبارات

تأكيد التسجيل المعتمد مرة بعد عبور الصحيح أضيف في `reading-letters-trial/src/App.tsx` فقط، فوق النسخة المعتمدة ذات النجوم. بداية الجولة تبقى مرة. مؤقت المحرك قد ينقل الجولة أثناء التأكيد، لكن صوت البداية التالية ينتظر انتهاء التأكيد ثم ٢٤٠ مللي ثانية. خطاف النجاح يحرس رقم الجولة لمنع التكرار، ويشمل الصحيح الخامس قبل إظهار النهاية. صوت الخطأ لا يشغل تسجيل الحرف. لا تغيير للنجوم أو السيارة أو الحلبة أو البوابات أو المساعدة أو عدد الجولات أو بايتات التسجيلات.

أكملت اختبارات بَ وجَ وأَ ويَ: لكل حرف ٥ تشغيلات بداية + ٥ تأكيدات صحيحة = ١٠ تشغيلات تلقائية مقصودة. أُدخل خطآن في أول جولة لكل حرف، بلا نطق حرف إضافي. لا تداخل، والفاصل المقاس بين نهاية التأكيد وبداية الجولة التالية نحو ٢٤٠ مللي ثانية. التأكيد الخامس سبق شاشة النهاية. اختبار إعادة السماع السريعة وتبديل الحرف والخروج نجح. اختُبرت كذلك ضغطة إعادة سماع أثناء تأكيد الصحيح: أربع تشغيلات حتى بداية الجولة الثانية، بلا تداخل، وانتظرت البداية نهاية السماع اليدوي وفاصل نحو ٢٤٠ مللي ثانية. سباق جمع النجوم بعد الإصلاح: ١٥ نجمة و١٥ نغمة وخمسة جولات و١٠ تشغيلات حرف، والمساعدة ٣ ثم ٢ ثم ١ دون إعادة النجوم. اختبارات بَ وجَ نجحت أيضًا مع تفويت عشر نجوم من ١٥.

اختبار قديم/جديد حتمي دون خيارات القراءة شغل ٦٠٠ إطار وقارن الحركة والسرعة وموضع السيارة وحالة خطأ البوابة والتعتيم والصورة النهائية، وكانت النتائج متطابقة. وعكس مواضع المحرك الأربعة يعيد `script.js` الأساسي بايتًا ببايت. فحص بنك البيانات: ٧٦٣ تحققًا و٧٢ سؤالًا وبصمات الأصول سليمة. هذا لا يساوي فحصًا شاملًا لكل ألعاب التطبيق. جميع الاختبارات بمتصفح أو تشغيل برمجي، لا هاتف ولا سبورة حقيقية ولا طالب.

## تطبيق الحزمة في نسخة عمل آمنة

احفظ نسخة وابدأ من شجرة نظيفة. لا تطبقها مباشرة فوق نسخة بها تغييرات مجهولة.

```
git fetch origin main
git rev-parse origin/main
git status --short
git bundle verify /path/to/reading-letters-final.branch.bundle
git fetch /path/to/reading-letters-final.branch.bundle reading-race/letters-trial:reading-letters-review
git switch reading-letters-review
git log -1 --format=%H
git diff --stat origin/main...HEAD
git diff origin/main...HEAD -- script.js
```

إذا لم يكن main هو الأساس المذكور، توقف لمراجعة الفرق. لا تستبدل script.js من نسخة قديمة ولا تفترض صلاحية patch تلقائيًا. bundle يحتاج الأساس في المستودع، وليس نسخة كاملة من كل تاريخه. ZIP المصدر لا يكرر التسجيلات الأصلية؛ يحتاجها من المستودع. patch النصي اختياري بديل للقراءة والتطبيق فوق الأساس نفسه، وليس فوق bundle مرة ثانية.

الحزمة النظيفة تتغير في ثلاثة نطاقات فقط: أربعة مواضع اختيارية في `script.js`، بيانات `reading-race-data/` المعتمدة، ومصدر/توثيق/اختبارات `reading-letters-trial/`. وجود بيانات المقاطع والكلمات ضمن بنك المراجعة السابق لا يعني تنفيذ لعبتيهما، ولا يجوز إضافة مداخل لهما.

## تعليمات دمج سباق الحروف داخل التطبيق الرئيسي

هذه تعليمات عمل مطلوبة للمنفذ الآخر، وليست ادعاء بأن الملفات التالية جاهزة بالفعل. لا يوجد مضيف تطبيق أصلي مُسلّم باسم `reading-race-host.js`؛ يجب إنشاؤه ونقله بعناية من منطق المعاينة ثم اختباره. لا تضمّن مكتبة واجهة المعاينة أو تستخرج محركًا ثانيًا داخل التطبيق.

### ١. الملفات التي تُنقل أو تُضاف

- احتفظ بـ`reading-race-data/reading-banks.mjs` وتبعياته من المجلد نفسه، خصوصًا `allowlist.json` وملفات البنوك. استخدم `createReadingBank('letters')` فقط في الشاشة الجديدة. راجع import الفعلي داخل الموديول بدل حذف ملفات اعتمادًا على الاسم.
- انسخ `reading-letters-trial/src/reading-drive.js` و`reading-painters.js` إلى مجلد إنتاج جديد مقترح `reading-race/`، دون تعديل خوارزمية الجمع أو الرسام المعتمد.
- أنشئ `reading-race/reading-race-host.js` كموديول JavaScript أصلي ينقل إدارة جلسة الحروف والتحقق والصوت وإلغاء الجلسة وحارس البداية والتأكيد من `App.tsx` إلى DOM التطبيق. `App.tsx` يستخدم React ومكونات خاصة بالمعاينة، فلا يصلح تحميله مباشرة في الموقع الأصلي.
- أنشئ `reading-race/reading-race.css` بنقل قواعد `.lt-*` الضرورية فقط. استبدل متغيرات التصميم الخاصة بالمعاينة بقيم محلية تحت `#readingLettersRace`، دون قواعد عامة أو تغيير `style.css` كله.
- لا تنقل `engine-original.js` أو `letter-bytes.json` أو غلاف الاستضافة أو صورة البطاقة إلى إصدار التطبيق. الأول استخراج للتجربة فقط، والثاني تضمين خاص بالمعاينة. التطبيق يجب أن يستخدم محرك `script.js` نفسه وملفات التسجيل الأصلية من مساراتها.

### ٢. الربط بالمحرك الأصلي

في المضيف الجديد، استدعِ `rr3CreateEngine` الموجود في `script.js` بعد تحميله، بنفس إعدادات التجربة: `standalone:true` و`layout:'gate'` و`mode:'step'` و`reduced:true` و`collision:0` و`theme:9` و`track:'calm'`، وخمس جولات من حرف مختار ثابت. مرر `readingCarPainter` و`readingInactiveGatePainter` و`readingAfterUpdate` و`readingRoadPainter` من مضيف القراءة فقط. تحكم القيادة والجمع للمضيف، وقرار عبور البوابة والمساعدة للمحرك.

إصلاح تأكيد الصوت يستخدم خطاف النجاح الموجود: عندما يصل `hooks.say` إلى مصفوفة أولها TARGET، شغّل تأكيد الجولة مرة ثم أنهِ callback بعد انتهاء التسجيل والفاصل. عندما يصل TARGET وحده استخدم حارس بداية الجولة وانتظر وعد التأكيد. رسائل الخطأ لا تشغل حرفًا. لا تجعل زر الاختيار هو من يمنح الصحيح، لأن الحكم يجب أن ينتظر العبور. انقل رمز إلغاء الجلسة وإيقاف الصوت والمؤقتات إلى teardown أيضًا.

تحذير لون مهم: سطرا تعديل `RR3_CAR_COLORS[0]` و`Object.assign(RR3_THEMES[9],...)` في أعلى المعاينة آمنان هناك لأن المحرك معزول، لكن نسخهما كما هما إلى التطبيق سيغير بيانات عامة قد تستخدمها ألعاب قديمة. لا تنقلهما. رسام سيارة القراءة يرسم ألوانه بنفسه ولا يحتاج تعديل لوحة السيارات العامة. للحفاظ على ألوان الحلبة المعتمدة، التعديل الإنتاجي الإضافي المقترح داخل `rr3CreateEngine` هو جعل اختيار theme يقبل كائنًا خاصًا اختياريًا مثل `cfg.readingTheme` مع fallback حرفي إلى `RR3_THEMES[...]`. مرر نسخة مستقلة من theme للقراءة فقط، وانسخ قيم التخصيص من المعاينة إلى هذه النسخة. هذا الموضع الخامس المقترح ليس منفذًا في الحزمة الحالية، ويجب مراجعته واختبار default regression قبل اعتماد الدمج.

### ٣. المدخل والخروج

في `index.html`، داخل `<section id="games" class="screen">` الذي يبدأ قرب السطر ٢٨٨٩ في الأساس، أضف بطاقة منفصلة باسم «سباق الحروف بالفتحة». لا تستبدل بطاقة «سباق الحروف» الحالية قرب السطر ٢٩٧٤ ولا تعدّل مسارها. أعطِ الجديدة id مستقلًا مثل `openReadingLettersRace` واربط listener في الموديول الجديد، لا استبدال startRaceStage.

أضف section جديدًا `id="readingLettersRace" class="screen"` قبل إغلاق حاوية الشاشات، مع جذر المضيف. أضف link للـCSS في head بجوار أنماط الألعاب، و`<script type="module" src="reading-race/reading-race-host.js"></script>` بعد `<script src="script.js"></script>` قرب السطر ٥٨٨٤. هذه أسماء مقترحة جديدة وليست ملفات موجودة حاليًا.

فتح الشاشة يستدعي `rr3Teardown()` لإيقاف أي سباق قديم إن كان نشطًا، ثم `showScreen('readingLettersRace')`، ثم يبني منتقي الحروف. زر «اختيار حرف آخر» ينهي جلسة السباق ويعيد المنتقي داخل الشاشة. زر «العودة للألعاب» ينهي الجلسة والصوت والـRAF والـURLs ثم `showScreen('games')`.

في `script.js` داخل `showScreen(screenId)` قرب السطر ١٩٢٧، أضف فحصًا محميًا في البداية ينادي teardown القراءة إذا كانت نشطة والوجهة ليست readingLettersRace. ذلك يمنع استمرار الصوت عند مغادرة الشاشة من التنقل العام. لا تغيّر StudentStore أو بيانات النجوم أو تقدم الطلاب. يملك المضيف الجديد حالته في الذاكرة فقط.

### ٤. الصوت والمسارات

المصدر النهائي للمسارات والبصمات هو `reading-race-data/allowlist.json`، الحقول sourcePath وaudioSha256 للسجلات section=letters، وعددها ٢٧. مثلًا `assets/audio/educational/letters/letter_02_ba.mp3` و`letter_05_jeem.mp3`. لا تخمّن أسماء بقية الملفات ولا تعيد تسميتها. استبعد letter-9 وذَ من كل دور، بما فيه المشتتات. في loadBytes حمّل مسار السجل نفسه من جذر التطبيق المناسب لمسار GitHub Pages، ثم تحقق قبل إنشاء Blob. حل المسار بالنسبة إلى قاعدة التطبيق لا إلى مجلد الموديول الجديد. لا تغير قائمة السماح ولا البصمات ولا الملفات. لا تستخدم TTS بديلًا عند الفشل. نغمة النجمة مولدة ومستقلة، وليست تسجيلًا معتمدًا جديدًا.

### ٥. المحمول والسبورة

احتفظ بارتفاع المضمار ٣٢٠ تقريبًا عند العرض الضيق و٣٨٠ على المحمول و٥٢٠ على العرض الكبير، وبالأزرار الكبيرة وترتيب يسار/وسط/يمين الذي يوافق الطريق. استخدم ResizeObserver وسقف الدقة الأصليين في المحرك، ولا تُنشئ حلقة رسم أخرى. لا تمنع touch عالميًا، بل على منطقة التحكم اللازمة فقط. الأرقام ٠١٢٣٤٥٦٧٨٩ في عناصر الطالب. راجع ٣٢٠ و٣٩٠ و١٢٨٠ والاتجاهين ولوحة المفاتيح، ثم اختبر جهازًا فعليًا إن أُتيح، دون نسب نتائج المحاكاة إليه.

### ٦. منع التأثير على الألعاب القديمة

لا تغير `startRaceStage` أو `rr3Launch` أو `rr3Distractors` أو مفاتيح الطالب. المواضع الأربعة الحالية اختيارية وتعود للمسار القديم إن غابت الإعدادات. لا تمرر إعدادات القراءة من أي مضيف قديم. أعد اختبار الحركة والصورة الافتراضية بعد إضافة theme الاختياري المقترح، ثم جرّب سباق الحروف القديم والجمع ولعبة أخرى وخروجًا متبادلًا مع الشاشة الجديدة. لا يكفي نجاح بناء الملفات.

### ٧. تعديلات ملفات التطبيق الرئيسية المطلوبة بدقة

- `script.js`: الاحتفاظ بالمواضع الأربعة الحالية داخل RR3-ENGINE فقط؛ اختيار theme الاختياري المعزول المقترح عند السطر الأصلي `const th = RR3_THEMES[...]` داخل rr3CreateEngine؛ وفحص teardown القراءة داخل showScreen. لا نسخ محرك جديد ولا تغيير منطق عبور أو سرعة.
- `index.html`: بطاقة جديدة داخل games، section جديد، link CSS، script module بعد script.js، كما سبق. لا استبدال الشاشة القديمة.
- `service-worker.js`: عند الإصدار الفعلي، ارفع CACHE_VERSION الحالي في رأس الملف، وأضف ملفات الإنتاج الجديدة وتبعيات القراءة إلى APP_SHELL بحسب سياسة التحميل المختارة. لا تضف مجلد المعاينة أو tests. اختبر أول تحميل وتحديث كاش قديم وتحقق من تحميل التسجيلات، ولا تعدّل KNIGHT_CACHE أو قواعد الألعاب الأخرى. لا تعد العمل دون إنترنت مدعومًا قبل اختباره.
- ملفات جديدة تحت `reading-race/` للمضيف والأنماط والوحدتين، مع بنك البيانات المعتمد في مساره. لا تعديل لازم لـnav.js إذا استُخدم showScreen وبطاقة listener مستقلة، لكن تحقق من مسار العودة العام في النسخة الفعلية.

قبل أي إصدار: راجع فرق هذه الملفات فقط، وأكمل الاختبارات الصوتية الأربعة حرفًا حرفًا، الصحيح الخامس، خطأين، إعادة سماع يدوية أثناء التأكيد، تبديل الحرف والخروج أثناء الصوت، جمع/تفويت النجوم، ثم انحدار الألعاب القديمة وحالة الكاش. إذا فشل أي منها أو ظهرت حاجة خارج النطاق، ارفعها للمالك قبل الدمج أو النشر. المالك لم يطلب تنفيذ هذه التعليمات في هذا التسليم.
